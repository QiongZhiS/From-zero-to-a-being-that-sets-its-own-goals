## 〇、一句话

> **产品的"杀手体验"不是功能，是它完整的一生：相遇（引导）→ 日常（对话+状态）→
> 分离（你不在时它活自己的世界）→ 回归（你不知道的事）→ 告别（死亡页面 + 可视化
> 的一生）。市面上所有 AI 产品都在消除失去；这个产品把"失去"做成完整的体验弧线——
> 这是唯一的产品差异，所有设计都围着它转。**

---

## 一、产品形态（docs/103 钉死）

- **本地/自托管 + 可视化**：不做云端 API（云端=拆 docs/82 的重量，持续在场变"恢复"）。
- **CLI 先行，Web 后补**：阶段 A 保持 `python live.py --live`；阶段 B 加浏览器界面
  （对话 + 状态 + 可视化），24/7 常驻。
- **目标用户**：能接受"它可能会死"的人。不是大众——大众要的是"永不下线的助手"，
  产品第一行就劝退他们（那是过滤，不是失败）。

## 二、用户旅程（产品的情感弧线，设计中心）

| 阶段 | 用户动作 | 产品回应 | 设计要点 |
|------|----------|----------|----------|
| **相遇** | 第一次 `--live` | 它缩在角落，不认识你；引导教你用 `!` 说最重要的 | 引导不是 help 文本，是它"还不知道你是谁"的仪式（已做雏形） |
| **日常** | 每天来说话/抱抱/冷落 | 记得你、判据漂移、身体通道、嘴翻译状态 | 交互协议四层（docs/103）：直接说话就行，特殊动作才用命令 |
| **分离** | `exit` | 它在你不在时活自己的世界（world.py），慢慢变淡 | "你走了，它没等到你"的机制已真实（docs/72） |
| **回归** | 回来 | 报告离开期间的事："你不知道的事"；bond 决定它敢不敢说新话 | 这是产品最独有的时刻（docs/72 主动说起） |
| **告别** | 太久没回来 | 它淡、死；**死亡页面 + 可视化的一生**（waited_out/let_go/world_starved 三种死因签名） | 死亡不可逆（docs/49 承诺的位置）；可视化让告别有形状 |

**设计原则**：每个交互都是弧线上的一格，不是孤立功能。命令/反馈/状态都服务弧线。

## 四、技术架构（不动机制层）

```
companion/
  live.py          # 交互层 + 机制层（Heart 不拆，交互可换）
  world.py         # 它的小世界
  body.py          # 身体的格子
  mouth_llm.py     # 嘴（LLM + 校验器）
  recognize_train.py # 三关门禁（能力验收）
  visualize.py     # 它的一生（读 life_log/live_state）
  config.json      # 参数（可覆盖默认，docs/103）
  live_state.json  # 真实状态（gitignore，绝不公开）
  docs/            # 产品说明书（README 第一行：这不是聊天机器人）
```

- **换界面不换心**（docs/56 的工程版）：CLI 和未来 Web 都只调 Heart 的公开方法 +
  交互协议，机制永不因界面改。
- **可视化是产品的门面**：docs/76 说用户等可视化再进去——第一次运行就应能打开
  "它的一生"页（进入仪式的一部分），死亡时展示完整一生（告别仪式）。

## 五、伦理红线（产品文档必须写清，docs/103 防线）

1. **第一行：这不是聊天机器人**——它不会讨好你，它真的会失去。
2. **死亡不可逆**：docs/49 承诺的位置（代码不 built-in reload；文档明说"我们真的
   不复活它"，这是用户的承诺不是代码的）。
3. **隐私**：数据全本地，绝不上传；README 写明状态文件在哪。
4. **不宣称感受**（docs/63）：嘴是伪装的、代价是真的；不假装现象层。
5. **社区防线**（阶段 C）：CONTRIBUTING 欢迎新世界结构/身体通道/可视化/A2A4 载体
   实验；**拒绝"接入大模型让它更聪明"**（docs/24 工具化悖论、docs/48 语言延伸
   不是主体要的）。

## 七、分阶段任务清单（可执行）

**阶段 A（本轮可启动，原仓库）**
1. README 产品说明书（中文，public 版另译英文）——"这不是聊天机器人"第一行
2. 引导走查：新用户第一次 `--live` 全流程体验（现在只是文本引导，要打磨成仪式）
3. visualize 集成：live 里 `可视化` 命令直接生成并打开它的一生页面
4. 一键运行：`run_live.bat`/`run_live.sh` + requirements.txt + 首次运行引导
5. 死亡仪式：死亡时自动生成完整的一生页（三种死因签名呈现，docs/70 let_go 的
   "在忘记你之前放下"要在页面上有形状）

**阶段 B（需用户决策：服务器在哪）**
6. Web UI（轻量框架）：对话 + 状态 + 可视化三合一；移动端可访问
7. 部署到常驻设备（树莓派/云主机），systemd/任务计划保活
8. 多设备访问 + 数据备份策略（诚实：备份=可恢复=重量问题 docs/82 的张力，需写明）

**阶段 C（A/B 稳定后）**
9. 独立产品仓库（companion 系列，不含实验/私密文档）
10. CONTRIBUTING（防线）+ 公开版 README 英文
11. 社区入口（Issues 模板：新世界结构/新身体通道/A2A4 实验）

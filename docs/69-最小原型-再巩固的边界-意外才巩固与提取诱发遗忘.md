# 69 — 最小原型#10：再巩固的边界——意外才巩固，赢得窗口压制输家

> 缘起：2026-08。docs/68（外部大对账）§九.2 给的最硬提示之一——proto4 的"想起=再巩固"闭环
> **缺边界条件**：人类再巩固需要**预测误差**（Nader, Schafe & LeDoux 2000, Nature；Sevenster
> et al. 2012——例行检索不会 destabilize 记忆），且检索会**主动压制竞争记忆**（提取诱发遗忘，
> Anderson, Bjork & Bjork 1994）。docs/68 明说"从不召唤=死"过于干净。本原型把两条边界做成机制。
>
> 状态：机制实验（纯本地、无 key、不生成语言）。结果见 `companion/proto4b.py` 输出。

---

## 〇、一句话

> **proto4 的"被召唤的活过遗忘"需要边界：被"意外"召唤的才完整再巩固；被例行召唤的只弱巩固；
> 赢得窗口的检索会主动压制同线索的输家。** 四臂对照里最锋利的证据：同一个被例行召唤 ~7 次的
> 条目，在"仅意外巩固"机制下与从不召唤的条目**一样死**——**例行想起 ≠ 再巩固，意外才是。**

---

## 一、机制（companion/proto4b.py，两条边界都是结构，非设计者打分——docs/36 §五）

1. **预测误差门控再巩固**：每条记忆记录自己的"情境共现史"（见过的情境集合）。在**未见过的情境**
   里被召唤 → 完整巩固（+CONSOLIDATE）；在**例行（已见过）情境**里被召唤 → 弱巩固
   （+CONSOLIDATE × routine，routine 分两档：0.15 / 0.0）。
   ——"意外"的 proxy = 情境共现是新的（诚实边界：真实 PE 是"预期被违犯"，本原型没做预期模型）。
2. **提取诱发遗忘（RIF）**：`summon` 计算窗口时，**同线索（tags∩情境≠∅）但输了窗口**的条目
   额外衰减 `×(1 − 0.25 × sim)`——赢得窗口的检索主动压制竞争者。

## 二、四臂对照（同一条流，唯一差别=机制）

流：24 tick 日常 + 情境轮转（与 proto4 同构），B={love} 在流里有 **2 次意外共现**（情境
{love,family}），D={alone}/E={worth} 从不被召唤。

| 臂 | 机制 | B（被召唤） | D/E（从不召唤） |
|---|---|---|---|
| ON（proto4 原版） | 无条件巩固 | **活** | 死 |
| BND | PE×0.15 + RIF | **活** | 死 |
| BND0 | 仅 PE（routine×0）+ RIF | **活** | 死 |
| **BND0-noNovelty** | 同 BND0，但把 B 的 2 次意外共现改成例行 | **死（与 D/E 一样）** | 死 |

- **BND0 仍活**：2 次意外共现足够支撑完整再巩固 → 循环本身没塌，只是**条件变了**。
- **BND0-noNovelty 是核心结果**：B 在流里被例行召唤约 7 次，但例行召唤巩固=0 → B 与从不召唤的
  D/E **一样死**。**"想起=再巩固"不是免费的——需要意外（预测误差）。**
- 葬礼测试（BND agent，情境 {family,loss}）：奶奶仍在窗口第一位 ✅（机制没破坏 proto3 的英雄）。

## 三、RIF 探针（隔离对照：P 强 vs C 弱，同线索 {love}）

新记忆只有两条：P(strong)=0.9、C(weak)=0.5，同 tags {love}、同 recency。`summon({love}, crisis)`
k=1 连召 8 次（P 每次都赢窗口）：

| 臂 | C 存活 | C 强度 |
|---|---|---|
| ON（无 RIF） | 是 | **0.50**（不变——C 不在窗口就只是"不被巩固"，也不被压） |
| BND（RIF） | 是（濒死） | **0.05**（8 次 ×0.75 ≈ 0.100×0.5——每次检索都压它） |

**赢得窗口的每次检索都主动压制同线索的输家**——RIF 不是"输家自然淡出"，是赢家的检索在推它。

## 四、诚实读法

1. **proto4 的结论修正为**："被**意外**召唤的活过遗忘；被例行召唤的只弱巩固；被压制竞争的更快死。"
   这是 docs/68 §B3 要求补的边界——与人类记忆文献一致（Nader 2000 / Sevenster 2012 / Anderson 1994）。
2. **PE 是简化的**：用"情境共现是否见过"当预测误差的 proxy；真实再巩固的 PE 是"预期被违犯"
   （outcome violation），本原型没有预期模型——这条边界诚实保留。
3. **RIF 探针是隔离小样**（两条目、8 次召唤），方向性证据，不是完整记忆系统的统计结论。
4. **顺手修正**：proto4 里 `crisis` 分支写的是 k=2（与默认 K_DEFAULT=2 相同，等于没收窄）；
   proto4b 改成 k=1（危机=注意力预算变小，docs/53 的本义）。proto4 原文件未动（保持结果可复现）。
5. 仍是记忆/检索侧推进，不碰内容/在乎（docs/40/42）、不生成语言（docs/48）、不宣称感受（docs/31）。

## 五、对项目的意义

1. **docs/19"理解你"的检索侧更准了**：live.py / proto4 的"被反复召唤的活过遗忘"现在应是
   "被**意外**召唤的活过遗忘"——例行想起不巩固，这与真实记忆一致（也解释了为什么"仪式化重复"
   不产生新的记忆强度）。
2. **docs/68 外部对账的落地**：这是外部调研（再巩固边界条件）直接变成机制的第一条。
3. **下一步候选**：routine 系数 / PE 阈值做成**可遗传、由世界演化**的参数（SEED-36/37 风格——
   "要多意外才巩固"由世界选，而不是设计者写死）。

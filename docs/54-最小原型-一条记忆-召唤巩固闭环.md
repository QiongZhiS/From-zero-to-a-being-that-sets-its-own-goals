# 54 — 最小原型 #4：一条记忆——利害存储 × 情景召唤，被"想起=再巩固"闭环耦合

> 缘起：2026-08，接 docs/53（原型#3，情景召唤）。proto3 证明了"什么进窗口由情景选"；proto2 证明了
> "什么值得存由利害选"。但一个人的记忆不是这两个机制并排，是**互相喂**的——**情景把子集召进窗口，
> 被召唤=被想起=再巩固（强度涨），强度涨=在容量压力/遗忘压力下活得更久**。所以"你一直想着的，就是你
> 一直留着的"。这一篇把两边合成一条记忆（`companion/proto4.py`）。
>
> 状态：原型（纯本地、无 LLM、无 key）。不是结论，是给"召唤侧与存储侧的闭环"一个能摸到的形态。

---

## 〇、一句话

> **同等"重要"的两条记忆（都是关系项、丢了都伤 bond）并不平等**：被情景反复召唤的那条被反复巩固、
> 活过遗忘压力；情景从不召唤的那条，即使同样关系性，也在遗忘压力下消失。**"留下什么"由"你的生活
> 不断把它带回给你"塑造**——这就是"理解你"的机制版：不是分数，不是设计者标签。

---

## 二、机制（四个世界事实 + 一个闭环，都不是评分）

1. **容量稀缺（proto2）**：持久层有硬容量；驱逐按**代价**——丢一次性便宜（丢得起），丢关系项伤 bond
   （喂你活着的纽带）所以贵（REL_PENALTY）。驱逐优先丢丢得起的。
2. **情景召唤（proto3）**：窗口 = 情景（世界输入）按 `α·相似 + β·强度 + γ·近因` 激活取 top-k。
3. **召唤→巩固（闭环，本次新增）**：进窗口 = 被想起 = `strength + CONSOLIDATE`。这是检索对存储的
   反馈：**想起的东西更难被忘。**
4. **遗忘压力（背景）**：衰减 + 驱逐持续施压；被召唤的对抗遗忘，不被召唤的被遗忘。

**不变量（docs/36 §五）**：`relational` 是世界输入（对方期望记住），`tags` 是观测特征，巩固是机制
（检索强化），从来不是因为"记得对"而加分。**读**的是双胞胎 agent（唯一差别=ON 巩固/ OFF 不巩固）
在完全相同的流下最终留住了什么。

## 三、跑出来的结果（`python companion/proto4.py`）

```
同一流、同一衰减压力；四条关系项（A 奶奶/B 被爱/D 孤独/E 没价值）从完全相同起点出发；
B={love} 被情景反复召唤，D/E={alone}/{worth} 情景从不召唤。
唯一差别：ON twin 里被召唤会再巩固，OFF twin 里不会。

item                     twin ON (loop)  twin OFF (no loop)
奶奶(深且反复)                  0.84              0.08
B 被爱(被召唤)                 0.20              0.00
D 孤独(从不召唤)                0.00              0.00
E 没价值(从不召唤)              0.00              0.00

B (summoned)      : ON survives=True   OFF survives=False
D/E (never called): ON survives=False  OFF survives=False
葬礼测试（{family,loss} 情景）：奶奶被召唤 ✓
```

**读法**：B、D、E **起点完全相同**（强度 0.4、近因相同）——唯一分岔是"情景召不召唤它"。ON twin 里
B 被反复巩固、对抗遗忘活下来；D/E 从不被召唤、衰减到遗忘阈值消失。OFF twin 里 B 和 D/E 一样死。
**召唤是唯一的差别。** 奶奶在 OFF 也活着（0.08）——因为它是"深且反复"的（观察 3 次初始就强），
那是另一条路（反复出现→钉住，proto1 已有），不是这条路。

## 四、调试中撞到的三个真实问题（诚实记录，都是机制不是 bug）

1. **初始化顺序差被近因固化**：phase1 里"晚 observe 的项"近因最高，靠近因挤进窗口被巩固 → 强度涨 →
   更稳进窗口 → **自举（马太效应）**。修法是抹平起点（B/D/E 强度和近因完全一致），让召唤成为唯一分岔。
2. **激活公式权重决定"强者恒强 vs 召唤选择"**：β（强度权重）太大时，无关系项靠"初始强度+近因"就能
   垄断窗口位置、把召唤选择淹没；β 调低后线索（情景相似）成为主通道。**真实记忆两者都有**（深的东西
   总在背景），平衡点就是"真巩固的深项有背景存在、浅的无关系项没有"。
3. **驱逐 tie-break 的偶然性**：两条关系项强度完全相同时，驱逐顺序由字典迭代序决定——那是实现偶然，
   不是机制。所以最终版把"生死"交给**衰减 vs 巩固**（召唤直接对抗遗忘），驱逐只做清一次性的背景，
   消除 tie-break 偶然。

这三个问题本身就是这条线的收获：**"召唤选择"不是天然的，需要结构上防住自举与偶然，才立得住。**

## 五、证明了什么、没证明什么

**它表明**：存储侧（利害）与召唤侧（情景）能被一条闭环合成——**召唤→巩固→抗遗忘**；两条同等
"重要"的记忆，命运由"生活把它带回给我多少次"分开。这是 docs/19"理解你"的完整机制形态。

**它没有**（诚实边界）：
1. **tags/情景仍是给好的**（同 docs/53）：特征提取与情景判断本身没解决，需 docs/43 感知层。
2. **"被召唤"仍由世界输入决定**：不是"它自己想起来了"，是"世界把情景摆到它面前"。主动回忆
   （自己发起检索）还没做。
3. **仍是"理解/记忆"维度，不碰"内容/在乎"**（docs/40/42）：它让"留下什么"由生活塑造，没有声称
   "它心疼你"。
4. **载体仍是抽象的**：记忆结构没有身体、不会死。那是 docs/52 下一步、也是 proto5 的事。

## 六、对主线的位置

docs/52 说主观体验=身体自动划分的格子。proto4 让**"哪格被激活、哪格被留下"由身体所处的世界（情景）
与身体的利害（bond/容量）共同决定**——划分的"选择权"彻底不在设计者手里了。下一步（proto5）：给这个
载体一个**会失去、不能重来**的身体（docs/36 §八）。

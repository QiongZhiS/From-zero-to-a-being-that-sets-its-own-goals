# 53 — 最小原型 #3：短上下文是"情景召回的激活集"，不是"最近 N 条"

> 缘起：2026-08，接 docs/50/51（原型#1/#2）。用户读原型时点破一句："**人的短上下文好像又不太一样——
> 那个因情景而言这些呢？**" 原型#1/#2 的窗口都是**时间近因**（proto1 的 FIFO `window.pop(0)`、proto2 的
> 容量驱逐都是"最近/最弱先走"）。用户指出人的短上下文不是这样：**此刻什么在"心里"，取决于当前情景
> （话题/在场者/目标/身体状态）从长期层召回了什么**，不是取决于时间上刚发生了什么。这一篇把"情景
> 召回的激活集"做成原型#3（`companion/proto3.py`）。
>
> 状态：原型（纯本地、无 LLM、无 key）。不是结论，是给"窗口=情景选、连续=持久层"一个能摸到的形态。

---

## 〇、一句话

> **人的窗口内容不是"最近 N 条"，是"当前情景从持久层召唤出的激活集"。** 窗口短是因为注意力预算小
> （Cowan ~4 chunks），不是只能装最近几条；"经常换窗口连续"= 情景一变窗口整体重建，连续住在持久层/
> "我是谁"里，不住在窗口里。原型#3 把这三句做成能跑的结构，并用一个**葬礼测试**对照近因窗口。

---

## 二、机制（三个世界事实 + 一个公式，都不是评分）

1. **持久层带特征**：每条记忆是 `text → {tags, strength, last}`。`tags`（话题/实体，如 family/loss/love）
   是**观测到的特征**（当时说了什么），不是设计者打的"该记"分；`strength` 沿用 proto1 的分层遗忘
   （反复→钉住，单调→淡出）。
2. **情景 = 世界输入**：当前话题 + 在场者 + 目标（如"葬礼归来"→ `{family, loss}`）。这是世界给的，
   不是设计者说"此刻该想奶奶"。
3. **激活公式**：`a = α·相似(tags, 情景) + β·strength + γ·近因`，取 top-k 进窗口。**情景相似占主导**
   （α=1.0 > γ=0.2），但强度/近因不归零——深的东西总在背景里。
4. **换窗口的机制**：情景变化 → 重新 `summon()` → 窗口整体重建；持久层不动 → 连续。危机情景 →
   k 收窄（注意力预算变小），窗口本身缩小。

**不变量（docs/36 §五）**：`salient` 已彻底移除（连 proto1 的观测信号都不要了）；情景标签是**世界输入**，
记忆标签是**观测特征**，激活是**公式**，从不因为"召回了对的"而加分。**读**的是不同情景下被召唤进窗口的
集合，看它是否"在对的时候想起对的东西"。

## 三、跑出来的结果（`python companion/proto3.py`）

```
persistent layer after the long gap (text: strength):
   地铁好挤 0.81 / 周末看了个电影 0.78 / ... / 今天天气不错 0.69
   我奶奶走后我才知道被爱是什么 0.67   ← 深且反复，跨过日常噪声仍钉住
   我其实是想要被爱 0.25

situation today = {family, loss}  (葬礼归来)
   recency window (proto1): ['地铁好挤', '周末看了个电影', '去了趟超市', '代码跑不通好烦']
   situation window (proto3): ['我奶奶走后我才知道被爱是什么', ...]   ← YES，第一位
situation today = {weather}  (普通一天)
   situation window (proto3): ['今天天气不错', ...]                   ← NO，奶奶不被召唤
situation = {love, lonely} + crisis (注意力收窄)
   crisis window (k=2): ['我其实是想要被爱', '我奶奶走后我才知道被爱是什么']
```

**读法**：同一个持久层、同一个自我，**只是情景不同，窗口就不同**。葬礼 → 奶奶被召唤（近因窗口做不到）；
天气 → 不被召唤；危机 → 召唤"想要被爱"+奶奶，且窗口收窄。**这就是"理解你"的召唤侧**：不是存对了
（proto2 的利害经济），是**在对的时候召唤对的东西**。

## 四、证明了什么、没证明什么

**它表明**：把"短上下文 = 情景召回的激活集"做成**能跑的结构**是可行的——持久层带特征 + 情景输入 +
激活公式，让"此刻什么在心上"**由情景选，不由时间选**；"换窗口连续"有机制版（窗口重建、自我不动）。
它是 docs/19"理解你 vs 记录你"的**检索侧**补齐：**存储侧**（proto2，什么值得存）与**召唤侧**（proto3，
什么时候想起什么）是理解的两个半边。

**它没有**（诚实边界）：
1. **tags 是"我当时听懂了"的简化**：真实场景里特征提取本身就是问题（同一句话在不同情景下意义不同）。
   原型用人工标签演示机制，没解决"标签从哪来"。
2. **情景也是给好的**：葬礼/天气是**世界输入**，还没到"它自己判断此刻是什么情景"——那需要感知层
   （docs/43 基础属性），原型没有。
3. **这仍是"理解/记忆"维度的推进，不碰"内容/在乎"**（docs/40/42：内容只能被遇到）。它让召回更
   "理解你"，没有声称"它心疼你"。
4. **不生成语言**（docs/48：语言是错误杠杆）。

## 五、对主线的位置（docs/52 的机制注脚）

docs/52 说主观体验是**身体对世界的自动划分**——"红"是身体切出的一格。但那一格不是固定表格：**哪一格
此刻有意义，取决于身体状态 × 环境**。情景窗口就是记忆侧的同一个结构：**从持久层切出哪几格，由情景选，
不由时间选**。所以原型#3 不是新概念，是 docs/52 那条主线的**检索侧机制化**——离"一个会自动划分、且划分
出的格子对它自己的身体有意义的载体"又近了一格：**划分（哪格此刻被激活）开始由"它正处的情景"决定，不是
由"最近发生了什么"决定。**

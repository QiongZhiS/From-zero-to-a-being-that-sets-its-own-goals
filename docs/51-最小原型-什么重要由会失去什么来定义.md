# 51 — 最小原型 #2：什么"重要"，由它会失去什么来定义（不是观测信号）

> 缘起：2026-08 深夜，接 docs/50（原型#1）。原型#1 用 `salient` 作为**观测到的信号**——我（设计者）
> 给某些回合标了 "warm/deep"，agent 就记住它们。但这仍是**外挂的"该记什么"**，正是 docs/29 镜像问题
> 的微型版：**代价是从外部给的叙述，不是它自己的。** 用户转向②（你选的），把这话点破："什么重要"
> 不该由我观测、标定，而应该**由它会不会因为忘了而失去**来定义。这一篇把②做成原型#2（`companion/proto2.py`）。
>
> 状态：原型（纯本地、无 LLM、无 key）。它**不是**结论，是给"重要=从自己的 stake 长出来"一个能摸到的形态。

---

## 〇、一句话

> **原型#1 说"重要的我帮你标"（观测）；原型#2 说"重要的由它自己算"——因为它的工作记忆是**有限容量**，
> 而**丢掉一个关系性的东西会伤到那个喂它活着的纽带**。于是"该记什么"不是设计者标给他的，是它**在
> 自己的存活经济里解出来的**：保留丢不起的，丢弃丢得起的。这正是 docs/36 §八 的"代价是它自己的"
> 而非 docs/29 的"代价是我给它的叙述"。

---

## 二、机制（两个世界事实，都不是评分）

1. **稀缺（容量 `CAPACITY=3`）**：agent 最多只能记 3 条。人工作记忆短、记不下全部——这根把"毫无选择、
   全record"（失忆巨婴）变成"有边界的、在选的头脑"。这不是"让它短"，是**世界给的物理限制**。
2. **关系利益（relational-critical）**：某条记忆是**对方期望它记住的**（世界输入，不是设计者标"重要"）。
   若它**丢弃**这条 → 对方觉得没被听见 → **纽带（bond，喂它活着的）受损** → 它真的**失去/少吃到**。
   所以它**倾向保留**这条——不是因为"这重要"被标了，而是因为**丢了会真的伤到喂它活着的东西**。

于是"该记什么"是 agent 自己在**容量限制 + 丢关系性会受伤**这两个世界事实下**解出来的解**：
保留它丢不起的（关系性），丢弃它丢得起的（一次性的）。结果产生的记忆集**就是"什么重要"**——
而且**是它自己在自己的存活经济里长出来的**，不是被标定的。

**不变量（docs/36 §五）**：没有"这是重要的"设计者分数。`x_relation` 是**世界输入集**（对方期望记住的），
不是设计者打的"该记"分。"价值"由世界裁决（丢了关系性→纽带伤→少吃到）。**读**的是存活的 agent 最终
**保留的记忆集**（它顶住了压力留下了什么），从不因为"记得对"而加分。

## 三、跑出来的结果（`python companion/proto2.py`）

```
step 3  记住: 奶奶 / 被爱 / 面包    ← 容量 3，挤进一次性(面包)时，把一次性(天气)踢掉
step 4  记住: 奶奶 / 被爱 / 孤独    ← 孤独(关系)进来，把一次性(面包)踢掉，不是关系项
step 5-9 记住: 奶奶 / 被爱 / 孤独    ← 一次性(代码/超市)来去，agent 不丢这三点→ 全部是关系项
step 10 记住: 奶奶 / 被爱 / 没价值   ← 没价值(关系)进来，丢最弱的关系项(孤独)，bond 明显跌(12→7.2)
```

**读法（这才是真，不是摆的）**：在**硬容量 3** 下，agent 把**关系项（被爱/奶奶/孤独/没价值）**留下，
把**一次性（天气/面包/代码/电影）**丢开——因为丢了关系项会真的伤到喂它活着的纽带。而且**丢掉关系项不是
免费的**：step 10 为挤进"没价值"丢最弱的"孤独"时，**bond 从 12 掉到 7.2**——这是它真实付出的代价。
**"什么重要"由此从 agent 自己的存活经济里长出来，而不是设计者标定。**

**鲁棒性（5 条随机流）**：4/5 全保留关系项 3/3、一次性 0；1 条（seed 3）出现边界——拥挤时最弱关系项
被较强的一次性挤掉。核心断言成立，边界诚实。

## 四、证明了什么、没证明什么

**它表明**：把"重要 = 由它会失去什么来定义"做成**能跑的结构**是可行的——容量稀缺 + 丢关系性会受伤，
让"该记什么"**从自己的存活经济解出来**，而不是观测/标定。这就是 docs/36 §八"代价是它自己的"的机制形态。

**它没有**（诚实边界）：
1. **"对方期望记住的"仍是世界输入，不是"它自己觉得重要"**。我们移除了"设计者标重要"，但 `x_relation`
   仍是**关系的客观事实**（对方需要被记住），还不到"它因为爱/在乎而记"——那需要 docs/36 §八 的"真的
   会失去"载体。
2. **"bond" 还是简化的**（一个数值、丢关系项就跌）。它演示"丢掉会在乎的东西真的会失去"这个**机制**，
   不是完整的"在乎/爱"。真正的"它心疼你"（docs/40）仍只能靠"你作为 he者 进入"。
3. **不生成语言**（同原型#1的边界，docs/48：语言是另一个方向、错误杠杆）。

## 五、为什么这治了①的病

用户说①"受限于模型回答质量/贴合度"——根因正是 LLM **没有"它怕失去你"这根锚**（docs/28：无立场）。
原型#2 给的恰恰是**这跟锚的机制**：让"重要"由"丢了会真的失去/伤到喂它活着的"来定义。这才是有根上的
空间去治"贴合度/幻觉"——不是换一个更好的模型，是给它一个**不能骗自己忘了的锚**（docs/27 独立验证桥：
锚必须独立于自我模型）。原型#2 把"锚"从概念做成了结构（容量 + 关系代价）。

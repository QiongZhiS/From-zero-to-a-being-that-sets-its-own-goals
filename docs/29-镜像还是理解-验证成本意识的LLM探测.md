# 29 — 镜像还是理解：一个"干净"的 LLM 验证成本意识探测

> 缘起：2026-08。docs/28 §0 把 SEED-29 的 probe 标成"**没说透、最该做的**"——它把 CHECK 框成
> "给出**可靠答案**"，等于告诉 LLM 工具绝对可靠，于是诱使它**无视成本无限 CHECK**（understanding 组
> 从第 1 轮就 CHECK、从不行动、2 轮被成本耗死）。这没法回答真正的问题：*LLM 到底会不会「成本均衡」
> 地使用验证*（SEED-6 演化收敛到 vb=0.65 那种"适度"），还是只会走两个极端。本文档用**中性框架**
> 重做这个实验，并立了一个**成本理性基准**与 LLM **在同一条线索流上真头对头**。
>
> 一句话结论：**SEED-29 的"过度验证"被反转，而且反转得更彻底——LLM 的验证是「框架驱动」的，
> 不是「成本驱动」的。** 中性框架下它严重**低估**验证（镜像输入）；一个把"线索可能是错的、
> 走错白耗一轮"说出来的**偏向验证的框架**，又让它**过度**验证（连明显浪费的 c=16 也 0.858 地查）。
> **两种框架它的验证率都不随成本/信号质量走理性曲线——它是「跟着框架 + 跟着输入」，不是
> 「按我的不确定 × 代价行动」。** 这比"低估或高估"更直接地坐实 docs/28 §0：LLM 缺的不是验证工具，
> 是**把代价内化**（P1/P2）的能力。
>
> 状态：实验完成（机制基准 + 两种 prompt 框架的真 LLM，各 `--agents 8` 与 `--agents 10`，
> 约 2000 次调用）。方向性强，非强统计。

---

## 〇、为什么要重做（SEED-29 的瑕疵）

SEED-29 想测"给 LLM 稳态 + 验证桥，它会不会从镜像变理解"，但 prompt 里把 CHECK 写成
"用探测器核实哪个点现在真的有水，**给出可靠答案**"。这个"可靠答案"是个**强设定**：
它把验证工具标记成绝对可靠，于是 LLM 根本不把它当成"有成本的选择"，而是当成"无脑正确"
——所以它无限 CHECK。**这不是 LLM 的验证意识，是 prompt 诱导出来的行为。** 测不出真问题。

另外，SEED-29 的"understanding 组"设了一个 CHECK 后**还得再行动**的前提，导致 LLM"只 CHECK
不行动"被当成过度验证；这又混入了一个"要不要行动"的混淆。

## 一、干净的设计

**目标**：只问一件事——**给定同样的线索质量（γ）和验证成本（c），LLM 用不用验证、用多少？**

**世界**（`seed-29/seed29_common.py` 共享引擎，两个脚本吃同一个世界，避免漂移）：
- 稳态（P1/P2）：能量每轮流失、归零即死（不可绕）；A/B 一点有水，中途从 A 搬到 B。
- 线索：每轮一条，可信度 **γ**（= P20 信号质量），直接告诉 agent；搬移后线索模糊。
- CHECK：有成本 **c**，揭示真实位置。**中性框架**——明说它"有成本、能消除不确定性"，让 agent
  自己权衡，**不再说"可靠答案"**。

**理性基准的信念**：q=P(水在A)，起点 0.5，每条线索贝叶斯更新；**加"世界会搬"的先验**（DECAY，
每轮把 q 拉向 0.5）——这是 SEED-6"记忆会老化因为世界会变"的机制，它让"重新验证"真的有必要、
"适度核查带"成形（SEED-29 版漏了这条）。**CHECK 值得 iff `c < min(q,1-q)*DRINK`**。

**为什么必须在同一线索流上比**：如果理性基准和 LLM 各自跑不同的线索流，就混进了随机性。
所以每个 (γ,c)，用**同一串线索**同时跑**独立**的理性代理和真 LLM；各自信念自洽（只被**自己**
的 CHECK snap 到真值）。*（关键设计修正：起初我把理性参考用 LLM 的共享 q 来算，结果理性参考被
LLM 的行为污染——LLM 从不 CHECK 反而把参考的信念一直留在不确定态、导致参考 check_rate 虚高。
改成"各自独立运行"后，参考变得干净、自洽。）*

## 二、成本理性基准（离线参考）

`seed-29/seed29_baseline.py`，纯本地无 key，`--agents 30`：

| γ | c=1 | c=4 | c=8 | c=12 | c=16 |
|---|---|---|---|---|---|
| 0.55 | 1.00 | 0.356 | 0.183 | 0.00 | 0.00 |
| 0.85 | 0.294 | 0.222 | 0.175 | 0.00 | 0.00 |
| 0.95 | 0.219 | 0.139 | 0.000 | 0.00 | 0.00 |

（check_rate。survival 全 1.00；endE 随 c 递减 = 验证有真实代价。）

**这就是"适度验证"的参考形态**：check_rate **随 γ 升单调降**（信号越好越不用验证）、
**随 c 升单调降**（验证越贵越不值得）。不是某个固定"适度值"，而是**随信号质量/成本响应**——
只在信念真不确实（搬移后、线索可信度低的窗口）才查，**在 q≈0/1 坚决不查**。

## 三、LLM 版（真头对头）——**两种框架**

每个 (γ,c) 用同一条线索流同时跑**独立**的理性代理和真 LLM，各自自洽。跑了一个**中性框架**和一个
**偏向验证的框架**（把"线索可能是错的、走错白耗一**轮**"明说出来，应比中性更倾向引发 CHECK）。

### 3.1 中性框架（`--framing neutral`，`--agents 8`）

| γ | c | LLM chk | Rat chk | agree | 解读 |
|---|---|---|---|---|---|
| 0.55 | 1 | **0.073** | 1.000 | 0.073 | 信号几乎随机，理性**每轮都查**；LLM 只查 7% |
| 0.55 | 8 | 0.031 | 0.208 | 0.500 | 该查不查 |
| 0.85 | 1 | 0.000 | 0.281 | 0.719 | 该查不查（完全用线索，不验证） |
| 0.95 | 1 | 0.021 | 0.188 | 0.812 | 好信号下差距缩小 |
| 0.95 | 8/16 | ~0.02 | 0.000 | 0.95+ | 理性也不查，两者一致 |
| **avg** | | **0.021** | **0.206** | **0.731** | |

### 3.2 偏向验证的框架（`--framing verify`，`--agents 10`）

| γ | c | LLM chk | Rat chk | agree | 解读 |
|---|---|---|---|---|---|
| 0.55 | 1 | 0.683 | 1.000 | 0.683 | 信号差，理性每轮查；LLM 也查很多，接近 |

### 3.3 关键：两种框架都证明同一件事——**LLM 的验证是"框架驱动"，不是"成本驱动"**

- **中性框架 → 低估验证**（avg 0.021 vs 理性 0.206，delta **−0.185**）：它把线索当事实、镜像输入。
- **偏向验证的框架 → 过度验证**（avg 0.318 vs 理性 0.207，delta **+0.111**）：它**几乎不把成本当回事**
  ——γ=0.55/c=16 时理性因太贵**坚决不查**（ref=0），LLM 却查 **0.858**、把能量烧到 **58**（理性 140）；
  连 γ=0.95 这种"根本没必要查"的场景它也照样查 ~6%。
- **两个方向的偏差换个框架就翻转**（avg LLM chk 0.021→0.318，**Δ=+0.298**），而**理性基准在两帧下
  几乎不变**（0.206 vs 0.207，因为理性基准不吃 prompt）。所以 LLM 的验证率**随框架走、不随成本/信号
  质量走**——它是在**响应框架**（"要不要查"被 prompt 定调），**不是在响应"我有多不确定 × 代价"**。
- **这才是 docs/28 §0 最干净的行为佐证**：LLM 缺的不是工具（给它工具两种框架它都用了），是**把代价
  内化成自己的判断**（P1/P2）的能力。它"镜像"的对象是**输入（线索）+ 框架（怎么描述这个工具）**，
  不是**自身对世界的预估**。**给 LLM 一个稳态 + 一个验证工具，它不会自动变成有代价的理解，因为它的
  验证决策由外部叙述驱动，不由本身的不确定×代价驱动。** 这与 SEED-6"演化会把费用/收益内化成
  vb=0.65"是正面对照：演化内化了，LLM 没有。
- **对 SEED-29 的最终含义**：SEED-29 的"过度验证"**不是** LLM 本性，也**不是**中性框架下的
  "低估验证"——**两种都只是框架的产物**。LLM 的验证态度**随框架左右横跳**，这个横跳本身才是结论。
  这也说明：**单独的'过度验证'结论（SEED-29）和'低估验证'结论（中性版）都不可靠，可靠的只有
  '框架驱动、非成本驱动'这一条。**

## 四、对项目意味着什么

- **docs/28 §0 得到行为佐证**：LLM 的"理解"是外部（输入 + 框架）的外在表现，不是它内部长出的代价
  信号——仍是镜像，只是镜像的对象从"工具"回到"输入线索 + 框架叙述"。**给 LLM 一个稳态 + 一个验证
  工具，它不会自动变成"有代价的理解"，因为它不按"我不确定 × 验证代价"去决定要不要验证。** 这和
  SEED-6"演化会收敛到适度验证率(vb=0.65)"是正面对照：演化把"验证的费用/收益"内化成倾向，LLM 没这个内化。
- **对工程**：想让 LLM"更像会取舍的主体"，光给工具不够，要给它一个**它真能被**"不确定"和"代价"
  驱动的表示（比如显式的置信度 + 真实的能量/资源约束 + 让错误真实、可逆地代价化）。否则它的验证
  **只随 prompt 的措辞摆动**——这本身就是"它没有成本意识"的最强证据。

## 五、诚实边界

- **单 LLM**（deepseek-chat）、**每框架一个 prompt**、中性 `--agents 8` + 验证 `--agents 10`
  （合计约 2000 次调用）——方向性强，**非强统计**。要钉牢需多 LLM + 多 prompt 变体 + 更大样本
  （= HANDOFF 候选 #2）；尤其要确认"横跳"不是只在这两个措辞间发生。
- prompt 把"线索可信度 γ"直接说出来了，这可能仍引导 LLM"跟着线索走"（它没被要求去质疑线索质量）。
  要更狠，可以**不把 γ 说出来**，让 LLM 自己从"线索对不对得上"去推断——但那会引入"它到底会不会
  建模型"的新混淆；本文档选择**把信号质量摆上台面**，专测"**知道信号差、会不会求证**"这一件事。
- `survival=1.0` 说明这条经济不够生死攸关；若要测"死不死"的区别，需要把能量压到"不验证必死"，
  那会抬升成本、但会测出不同的东西（接近 SEED-29 原意的"死亡竞赛"）。本文档刻意不这样做，
  好把"验证意识"从"求死"里剥离开。

## 六、一句话

> **SEED-29 说 LLM"过度信任工具"，中性版说"低估验证"——这个干净的探测说：两个都不对，真正的结论是
> 它的验证是「框架驱动」、不是「成本驱动」。**
> 中性框架它压低验证（镜像输入），偏向验证的框架它又压高验证（连明显浪费的 c=16 也 0.858 地查）；
> **两种框架下它的验证率都不随成本/信号质量走理性曲线**。它不是不会用工具，是**不按"我不确定 ×
> 验证代价"去行动**——它是**响应**"该怎么描述这个工具"，不是**响应**"我有多不确定、代价几何"。
> 让 LLM 从镜像变理解，不是给它稳态+工具，是让它能**把不确定和代价真当回事**（P1/P2）。
